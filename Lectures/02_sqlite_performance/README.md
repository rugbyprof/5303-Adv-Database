# 04 — SQLite Query Performance

Why some queries on the [02_sqlite](../02_sqlite/) schema stay instant at a
million rows while others take a second or more, and how to tell from the
query plan. This lecture covers the concepts behind **Phase 3 ("gnarly
queries")** of [Assignment 01](../../Assignments/01_sqlite_api/):

- reading `EXPLAIN QUERY PLAN`
- `OFFSET` vs keyset pagination
- `LIKE` vs FTS5
- the cost of `COUNT(*)`
- window functions and frames
- gaps-and-islands
- multi-CTE reports
- random sampling
- anti-joins

## Quick start

```bash
cd Lectures/04_sqlite_performance
python ../../Assignments/01_sqlite_api/starter/scale_data.py \
    --db perf.db --customers 50000 --products 5000 --purchases 1000000 --skew   # ~10 s
sqlite3 perf.db ".read sql/01_reading_plans.sql"
```

Each script turns on `.eqp on` (print the plan) and `.timer on` (print the
time). Scripts that create indexes, FTS tables, or triggers drop them at the
end, so every script can be re-run in any order.
